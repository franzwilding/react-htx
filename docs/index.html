⚡️ reactolith

Hotwire Turbo, but for React. Render and morph a React app from server-generated HTML — Twig, ERB, Blade, Jinja, anything that prints strings.

reactolith lets you write React components directly in HTML so your backend stays in charge of routing, templates, permissions and URLs, while React stays in charge of interactivity. Return HTML from any controller; reactolith hydrates the page on first load and morphs the existing React tree in place on every subsequent navigation, form submit and live server push.

Why reactolith exists

I built reactolith because I wanted Hotwire Turbo — but for React.

Inertia.js is the closest thing in the React world, and it is great, but it is fundamentally a different model: Inertia replaces the page-level component on every visit. There is no equivalent of Turbo's morph — you cannot keep a sidebar's collapsed state, a video playing, or a half-typed form alive across a backend-driven navigation. The whole “page” is a single JSON-fed component that gets swapped out.

reactolith takes the Turbo approach instead. The server returns HTML, not JSON. reactolith parses that HTML, diffs it against the live React tree using React’s own reconciler, and updates only what changed. Component state, focus, scroll, open dialogs, mounted iframes — they all survive.

It makes the Majestic Monolith viable for React

That tiny difference unlocks something bigger. It makes the Majestic Monolith a serious option again for teams that want React on the frontend.

You can keep one Rails / Symfony / Laravel / Django app — one router, one auth layer, one set of URL helpers, one database, one deployment — and still ship a sticky, app-like React frontend on top of it. No SPA-shaped backend. No GraphQL gateway. No /api/v2 to keep in sync with the UI. Templates render HTML; reactolith makes that HTML interactive. Permission checks, flash messages, CSRF, signed URLs, i18n, route helpers — the things your framework already does well — just keep working, because the wire format is still HTML.

If you've ever looked at the Hotwire stack and wished you could use React components inside it, reactolith is that.

🚀 What you get

  • 🔌 Backend-agnostic — works with any backend (Symfony, Rails, Laravel, Django, …)
  • 🔄 Morphing navigation — like Turbo’s morph: the tree is diffed in place, React state is preserved across link clicks and form submits
  • 🛠 Use your existing backend helpers — Twig path functions, permission checks, flash messages, signed URLs — nothing has to be re-implemented in JS
  • 📋 Form support — the server can add or remove fields on a checkbox click without losing input state or focus
  • 🪶 No new backend layer — no JSON page-prop contract to maintain, no shadow API; your existing controllers and templates are the API
  • 📡 Real-time updates — Mercure SSE pipes server-pushed HTML through the same render path
  • 🧠 Scroll restoration — browser-like scroll behavior preserved between SPA-style navigations
  • 🧩 IDE autocomplete — generate JetBrains/VS Code web-types so <my-button> autocompletes like a native element

A 30-second tour

The minimum to get a working reactolith app is:

<!-- index.html (rendered by your backend) --> <div id="reactolith-app"> <h1>Hello world</h1> <my-button>Click me</my-button> </div> import { App } from "reactolith"; import { MyButton } from "./components/my-button"; new App(({ is }) => (is === "my-button" ? MyButton : null));

Any tag name with a hyphen (e.g. <my-button>) is treated as a custom React component — the rest of the HTML renders as native elements.
